## Key Architecture Takeaways

- **Point 1**: Hypervisor & container orchestration blueprint for Creating Container In PROXMOX Virtual Environment.
- **Point 2**: Architecture covers resource isolation, networking bridges, and high availability.
- **Point 3**: Optimized for Proxmox VE 8, modern Docker 27+, and kernel cgroups v2.


> [!TIP]
> **High Availability Cluster Recommendation**
> In modern virtualized datacenters (Proxmox VE 8.x), ensure guest configurations utilize VirtIO SCSI Single controllers with IOThread enabled, and isolate cluster corosync traffic onto dedicated 10GbE VLANs.

rnContainers are a lightweight alternative to fully virtualized machines (VMs). They use the kernel of the host system that they run on, instead of emulating a full operating system (OS). This means that containers can access resources on the host system directly.

rnrnrnThe runtime costs for containers are low, usually negligible. However, there are some drawbacks that need be considered:

rnrnrn
rn- rnOnly Linux distributions can be run in Proxmox Containers. It is not possible to run other operating systems like, for example, FreeBSD or Microsoft Windows inside a container.

rn
rn- rnFor security reasons, access to host resources needs to be restricted. Therefore, containers run in their own separate namespaces. Additionally, some syscalls (userspace requests to the Linux kernel) are not allowed within containers.
