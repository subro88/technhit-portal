## Key Architecture Takeaways

- **Modern SCP Protocol Transition**: In OpenSSH 9.0+, `scp` was rewritten to utilize the structured SFTP protocol rather than the legacy 1980s BSD `rcp` protocol, mitigating critical remote path injection vulnerabilities (CVE-2019-6111).
- **Rsync Delta Synchronization**: For recurring directory synchronizations and multi-gigabyte files, `rsync -avzP -e ssh` computes rolling Adler-32 and MD5 block checksums, transmitting only modified byte deltas (up to 99% bandwidth savings).
- **Hardened SFTP Chroot Jails**: External file drops must use OpenSSH's `internal-sftp` subsystem combined with `ChrootDirectory /data/sftp/%u`, `/usr/sbin/nologin` shell, and disabled TCP port forwarding.
- **Strict POSIX Jail Ownership**: The chroot root directory and all parent components must be owned by `root:root` with permissions `0755` or stricter. User write access is granted strictly within an interior subdirectory (e.g., `/data/sftp/user1/uploads`).

## 1. Architectural Comparison: SCP vs SFTP vs Rsync

Linux systems administrators and DevOps engineers have three primary protocols for moving files securely across SSH tunnels: **SCP**, **SFTP**, and **Rsync**. Selecting the correct mechanism dictates both the security posture and the bandwidth efficiency of your deployment.

<ArchitectureDiagram type="ssh-file-transfer" />

### Architectural Breakdown

| Dimension | Modern SCP (`scp`) | SFTP Subsystem (`sftp`) | Rsync over SSH (`rsync`) |
| :--- | :--- | :--- | :--- |
| **Underlying Wire Protocol** | SFTP (OpenSSH 9+) / RCP (Legacy) | SFTP Subsystem (Packetized RPC) | Custom Bidirectional Delta Protocol |
| **Interactive Shell Required** | Historically Yes (No in modern SFTP) | No (`internal-sftp` supported) | Yes (Requires `rsync` on both sides) |
| **Delta Chunking** | No (Re-transmits entire file) | No (Re-transmits entire file) | Yes (Transmits modified blocks only) |
| **Interrupted Transfer Resume** | No (Starts from byte 0) | Yes (via `reget` in interactive SFTP) | Yes (`--partial` / `-P` flags) |
| **Directory Sandboxing** | Difficult | Native (`ChrootDirectory`) | Difficult without containerization |
| **Ideal Production Use Case** | Ad-hoc one-off file transfers | Client/Partner data ingest, batch cron | Automated mirrors, deploys, backups |

## 2. Modern SCP: One-Off Rapid Transfers

Historically, `scp` executed the 40-year-old BSD `rcp` protocol. Due to severe security flaws where a rogue server could return arbitrary filenames outside the requested directory (CVE-2018-20685, CVE-2019-6111), OpenSSH 9.0+ replaced the wire implementation with the SFTP protocol by default.

<Callout type="warning" title="Legacy Systems Compatibility (-O Flag)">
When copying files to or from legacy embedded systems, hardware appliances, or older routers running dropbear or legacy OpenSSH (&lt; 8.0) that lack the SFTP server subsystem, modern `scp` may error with `subsystem request failed on channel 0`. To force `scp` to use legacy RCP mode for backward compatibility, supply the `-O` flag:
```bash
scp -O release.tar.gz admin@legacy-router.internal:/tmp/
```
</Callout>

## 3. Secure SFTP: Interactive Sessions, Batch Scripts & Chroot Jails

SFTP (SSH File Transfer Protocol) provides a complete remote filesystem manipulation interface: directory listings, attribute modifications, file renaming, and batch command execution.

### Interactive SFTP Command Reference

When logged in to an interactive `sftp>` prompt:
- Commands without prefix operate on the **remote** system (`ls`, `pwd`, `cd`, `mkdir`, `chmod`).
- Commands prefixed with `l` or `!` operate on the **local** system (`lls`, `lpwd`, `lcd`, `!command`).

```bash
# Connect with identity key
sftp -i ~/.ssh/id_ed25519 deployer@192.168.10.50

# Interactive Session Commands:
sftp> pwd                           # Print remote directory
sftp> lpwd                          # Print local directory
sftp> put app.zip                   # Upload local file
sftp> put -R ./dist                 # Recursive directory upload
sftp> get /var/log/syslog           # Download remote file
sftp> reget /var/log/large.dump     # Resume interrupted download
sftp> chmod 0600 production.env     # Modify remote permissions
sftp> bye                           # Disconnect
```

### Automated Non-Interactive Batch Transfers

To execute automated scheduled transfers in cron or CI/CD pipelines without human interaction, use the `-b` (batch mode) flag:

## 4. Hardening SFTP: Creating an Enterprise Chroot Jail

When third-party vendors or external clients need to upload files, they should **never** be granted an interactive Bash shell or access to system directories like `/etc` or `/var`. We construct an isolated chroot jail using OpenSSH's built-in `internal-sftp` subsystem.

<FileTree tree={[
  {
    name: "data",
    type: "directory",
    children: [
      {
        name: "sftp",
        type: "directory",
        children: [
          {
            name: "client1 (root:root 0755)",
            type: "directory",
            children: [
              { name: "uploads (client1:sftpusers 0700)", type: "directory" }
            ]
          }
        ]
      }
    ]
  }
]} />

<Callout type="danger" title="OpenSSH Chroot Security Requirement">
OpenSSH will refuse connection with `fatal: bad ownership or modes for chroot directory` if the directory specified in `ChrootDirectory` (and every directory above it) is not owned by `root:root` and writable only by root. The user must **never** own the root of the jail. Instead, create an inner `uploads/` folder owned by the user.
</Callout>

## 5. Rsync Over SSH: High-Performance Delta Synchronization

For synchronizing directory trees, web application deployments, and disaster recovery mirrors, **Rsync** is mathematically superior to both SCP and SFTP.

### The Rsync Delta Algorithm

Instead of re-copying entire files, Rsync:
1. Divides the target file on the remote server into contiguous blocks (typically 1KB - 8KB).
2. Computes two checksums for each block: a fast 32-bit rolling Adler checksum and a strong 128-bit MD5 hash.
3. Transmits the checksum table over SSH to the source server.
4. The source machine slides a window byte-by-byte across its local file, identifying identical blocks.
5. Only **unmatched bytes** (deltas) are compressed and transmitted across the network.

<Callout type="info" title="Trailing Slash Traps in Rsync">
In Rsync, a trailing slash on the source directory is critical:
- `rsync -a /src/dir /dest/` $\rightarrow$ creates `/dest/dir/` (copies the directory itself).
- `rsync -a /src/dir/ /dest/` $\rightarrow$ copies the **contents** of `/src/dir` directly into `/dest/`.
</Callout>

## 6. High-Throughput Cipher Optimization

By default, OpenSSH negotiates `chacha20-poly1305@openssh.com` or `aes256-gcm@openssh.com`. On low-power hardware, ARM single-board computers, or virtual machines without AES-NI hardware instructions, AES encryption can saturate the CPU, capping transfer throughput.

To maximize throughput across 10GbE or high-speed LAN networks, select the optimal cipher in your `ssh`, `scp`, or `rsync` invocation:

```bash
# On systems with Intel/AMD AES-NI hardware acceleration:
rsync -avP -e 'ssh -c aes128-gcm@openssh.com' ./data/ remote:/data/

# On ARM64 or low-power CPUs without hardware AES-NI:
rsync -avP -e 'ssh -c chacha20-poly1305@openssh.com' ./data/ remote:/data/
```
