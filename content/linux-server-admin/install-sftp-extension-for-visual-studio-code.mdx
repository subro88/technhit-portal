## Key Architecture Takeaways

- **Architectural Paradigm Shift**: Legacy SFTP plugins sync raw files across the network, whereas modern Remote-SSH runs a headless VS Code server engine directly on the Linux target.
- **Language Server Isolation**: Running LSP, linters, and debuggers natively on the remote host eliminates "module not found" errors caused by operating system discrepancies.
- **Integrated Port Multiplexing**: Remote-SSH automatically tunnels remote TCP ports (e.g., development web servers on port 3000 or 8080) directly to `localhost` on your local workstation.
- **Zero Inode Desynchronization**: Editing occurs directly against the remote filesystem; file overwrites, sync lag, and Git branch collisions inherent to SFTP sync are eliminated.

<Callout type="warning" title="Why Legacy SFTP Extensions Are Deprecated in Enterprise Workflows">
Third-party SFTP sync extensions (such as the legacy `liximomo.sftp` extension) download complete copies of remote repositories to your local workstation. If a remote background task, database migration, or Git rebase alters files on the server, local saves will blindly overwrite remote modifications without warning.
</Callout>

## Architectural Comparison: SFTP Sync vs. Remote-SSH

| Capability | Legacy SFTP File Sync (`sftp.json`) | Modern Remote-SSH (`ms-vscode-remote`) |
| :--- | :--- | :--- |
| **Execution Point** | Local Workstation (Mac/Windows) | Remote Linux Host (`~/.vscode-server`) |
| **Language Engines** | Must be installed locally on client | Uses remote system binaries and virtualenvs |
| **Integrated Terminal** | Separate local shell or external SSH client | Native PTY terminal running inside the Linux host |
| **Port Forwarding** | Requires manual SSH command-line tunnels | One-click GUI port forwarding with status tabs |
| **Git Operations** | Clumsy dual-state Git confusion | Native Git execution on the remote repository |
| **Network Traffic** | Full file payloads transferred on every save | Minimal JSON-RPC protocol diffs across SSH |

## Setting Up Remote-SSH: Step-by-Step

<Steps>

### Configure Your Local SSH Host Manifest

Define the remote target inside your client machine's `~/.ssh/config` file (or `C:\Users\<User>\.ssh\config` on Windows):

<CodeTabs tabs={[
  {
    filename: "~/.ssh/config",
    language: "apacheconf",
    content: `# Production Bastion Host
Host prod-bastion
    HostName 198.51.100.25
    User operative
    Port 22
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30
    ServerAliveCountMax 3

# Internal Cloud Compute Node (via Bastion Jump)
Host app-cluster-01
    HostName 10.10.20.15
    User sysadmin
    ProxyJump prod-bastion
    IdentityFile ~/.ssh/id_ed25519
`
  },
  {
    filename: "verify-ssh.sh",
    language: "bash",
    content: `# Test connecting to the defined host alias
ssh app-cluster-01 "uname -a && uptime"
`
  }
]} />

### Install the Official Remote - SSH Extension

Open the Extensions view in VS Code (`Ctrl+Shift+X` or `Cmd+Shift+X`) and install:

- **Extension ID**: `ms-vscode-remote.remote-ssh`
- **Publisher**: Microsoft

Alternatively, install via terminal CLI:
```bash
code --install-extension ms-vscode-remote.remote-ssh
```

### Connect to Host and Launch Remote Workspace

1. Press `F1` or `Ctrl+Shift+P` to open the Command Palette.
2. Type **Remote-SSH: Connect to Host...** and select `app-cluster-01`.
3. VS Code will establish an encrypted SSH transport stream, download and verify the lightweight `~/.vscode-server` daemon on the Linux host, and open a brand new window.
4. Click **File -> Open Folder** and select any remote server directory (such as `/var/www/technhit` or `/opt/docker-stack`).

</Steps>

## Legacy Fallback: Setting Up SFTP Sync (When Remote-SSH is Blocked)

In rare instances where a restricted corporate environment strictly blocks remote interactive shells and only provides SFTP access (such as locked-down cPanel shared hosting), use modern active forks like `Natizyskunk.sftp`:

<CodeTabs tabs={[
  {
    filename: ".vscode/sftp.json",
    language: "json",
    content: {
      "name": "Production-Static-Mirror",
      "host": "198.51.100.50",
      "protocol": "sftp",
      "port": 22,
      "username": "deployer",
      "privateKeyPath": "~/.ssh/id_ed25519",
      "remotePath": "/var/www/static-assets",
      "uploadOnSave": true,
      "useTempFile": false,
      "openSsh": false,
      "ignore": [
        "**/.git/**",
        "**/.vscode/**",
        "**/node_modules/**",
        "**/.env"
      ]
    }
  }
]} />

<Callout type="danger" title="Credential Security Warning">
Never commit `.vscode/sftp.json` to public Git repositories if it contains static passwords. Always configure `privateKeyPath` pointing to a local SSH key or add `.vscode/sftp.json` to `.gitignore`.
</Callout>
