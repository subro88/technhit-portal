## Key Architecture Takeaways

- **Event MPM Replaces Prefork**: Modern enterprise Apache deployments ditch legacy synchronous `mpm_prefork` and `libapache2-mod-php` in favor of asynchronous **Event MPM**, decoupling keep-alive HTTP sockets from PHP execution.
- **FastCGI Unix Domain Sockets**: PHP processing is offloaded to a dedicated **PHP 8.3-FPM** pool communicating over `/run/php/php8.3-fpm.sock`, saving over 75% system memory and eliminating loopback network latency.
- **Zend OPcache Acceleration**: Pre-compiles PHP script execution trees into shared memory (`shmop`), increasing requests-per-second (RPS) throughput by 5.4x compared to un-cached interpretations.
- **Hardened MariaDB Relational Storage**: Root database administration uses local Unix socket authentication (`auth_socket`), utf8mb4 multi-byte unicode schemas, and automated TLS/SSL protection.

## 1. Architectural Evolution: Modern LAMP vs Legacy 2016 Stacks

In legacy configurations (such as standard Ubuntu 14.04/16.04 tutorials), Apache utilized `libapache2-mod-php` embedded directly within each Apache worker process. Under `mpm_prefork`, every incoming HTTP connection—even an idle browser holding a keep-alive socket—consumed an entire 40MB - 60MB process. A sudden spike of 200 concurrent visitors would consume 12 GB of RAM, causing memory exhaustion and triggering kernel Out-Of-Memory (`OOM`) crashes.

The modern Linux architecture completely decouples the web server from the application runtime:

<ArchitectureDiagram type="lamp-stack" />

### Architectural Differences

| Component | Legacy LAMP (2016) | Modern Production LAMP (2024 / 2026) |
| :--- | :--- | :--- |
| **Apache MPM** | `mpm_prefork` (1 process per socket) | `mpm_event` (Asynchronous worker threads) |
| **PHP Execution** | `libapache2-mod-php` (Embedded) | `php8.3-fpm` via `mod_proxy_fcgi` |
| **IPC Transport** | Internal C Memory Space | FastCGI Unix Domain Socket (`/run/php/...`) |
| **Opcode Caching** | APC / Basic OPcache | Zend OPcache with JIT (Just-In-Time) compiler |
| **Database Engine** | MySQL 5.7 (Legacy MyISAM/InnoDB) | MariaDB 11.4 LTS / MySQL 8.0 (Strict InnoDB) |
| **Character Set** | `utf8` (3-byte incomplete subset) | `utf8mb4` (Full 4-byte RFC UTF-8 encoding) |
| **Database Auth** | Cleartext root passwords | `auth_socket` (Root login restricted to local root shell) |

## 4. Step 3: Hardening MariaDB 11 / MySQL 8.0

Modern MariaDB installations use `auth_socket` by default, meaning the root database user authenticates automatically when logged in as the operating system's `root` user via sudo: `sudo mariadb`.

Execute the automated interactive hardening utility:

```bash
sudo mariadb-secure-installation
```

Respond to the security prompts:
1. **Switch to unix_socket authentication?** $\rightarrow$ `Y` (Secures root access against remote credential cracking).
2. **Change root password?** $\rightarrow$ `n` (Unnecessary when using unix_socket; prevents password storage in cleartext).
3. **Remove anonymous users?** $\rightarrow$ `Y` (Prevents guest queries).
4. **Disallow root login remotely?** $\rightarrow$ `Y` (Ensures root can only connect via loopback socket).
5. **Remove test database and access to it?** $\rightarrow$ `Y` (Removes default unauthenticated schemas).
6. **Reload privilege tables now?** $\rightarrow$ `Y`.

### Creating an Application Database & Dedicated User

Never use the `root` database account in your application configurations (`wp-config.php`, `.env`, etc.). Always provision an isolated database with multi-byte unicode support:

```sql
-- Open administrative shell:
sudo mariadb

-- Execute provisioning query:
CREATE DATABASE app_production CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_520_ci;
CREATE USER 'app_user'@'localhost' IDENTIFIED BY 'StrongRandom_DbPass_2026!';
GRANT ALL PRIVILEGES ON app_production.* TO 'app_user'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

## 5. Step 4: Tuning PHP 8.3-FPM & Zend OPcache

PHP-FPM configuration resides in `/etc/php/8.3/fpm/`. Two key files govern performance and stability: `php.ini` (engine configuration) and `www.conf` (process pool limits).

### A. OPcache Calibration (`/etc/php/8.3/fpm/conf.d/10-opcache.ini`)

Ensure OPcache is configured with adequate RAM and revalidation parameters:

```ini
zend_extension=opcache.so
opcache.enable=1
opcache.enable_cli=0
opcache.memory_consumption=128
opcache.interned_strings_buffer=16
opcache.max_accelerated_files=10000
opcache.revalidate_freq=2
opcache.validate_timestamps=1
opcache.save_comments=1
```

### B. Process Pool Sizing (`/etc/php/8.3/fpm/pool.d/www.conf`)

By default, PHP-FPM operates in `dynamic` process management mode. Under heavy traffic, calculate your pool limits based on available memory:

$$\text{max\_children} = \frac{\text{Total Dedicated RAM (e.g. 2048 MB)}}{\text{Average PHP Process Size (e.g. 40 MB)}} \approx 50$$

```ini
[www]
user = www-data
group = www-data
listen = /run/php/php8.3-fpm.sock
listen.owner = www-data
listen.group = www-data
listen.mode = 0660

pm = dynamic
pm.max_children = 50
pm.start_servers = 10
pm.min_spare_servers = 5
pm.max_spare_servers = 15
pm.max_requests = 1000
```

Restart PHP-FPM to apply pool limits:
```bash
sudo systemctl restart php8.3-fpm
```

## 6. Step 5: VirtualHost Configuration & Directory Sandboxing

Create a hardened Apache VirtualHost definition at `/etc/apache2/sites-available/app.nhit.in.conf`:

<CodeTabs tabs={[
  {
    name: "/etc/apache2/sites-available/app.nhit.in.conf",
    language: "apache",
    content: `<VirtualHost *:80>
    ServerName app.nhit.in
    ServerAdmin webmaster@nhit.in
    DocumentRoot /var/www/app/public

    <Directory /var/www/app/public>
        # Disable directory listing and server-side includes
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>

    # Delegate PHP files directly to PHP 8.3-FPM FastCGI Unix Domain Socket
    <FilesMatch "\\.php$">
        SetHandler "proxy:unix:/run/php/php8.3-fpm.sock|fcgi://localhost"
    </FilesMatch>

    # Log file isolation
    ErrorLog \${APACHE_LOG_DIR}/app_error.log
    CustomLog \${APACHE_LOG_DIR}/app_access.log combined
</VirtualHost>`
  }
]} />

### Setting Strict POSIX Permissions on the Web Root

```bash
# Create directory structure
sudo mkdir -p /var/www/app/public

# Assign ownership to standard deployer user and www-data group
sudo chown -R $USER:www-data /var/www/app

# Restrict permissions: 0750 on directories, 0640 on files
sudo find /var/www/app -type d -exec chmod 0750 {} \;
sudo find /var/www/app -type f -exec chmod 0640 {} \;

# Enable the VirtualHost
sudo a2ensite app.nhit.in.conf
sudo apache2ctl configtest && sudo systemctl reload apache2
```

<Callout type="info" title="Why SAPI Name Must Be 'fpm-fcgi'">
Notice that `sapi_name` reports `fpm-fcgi`. If it reports `apache2handler`, Apache is still running legacy prefork `mod_php`. `fpm-fcgi` confirms that Event MPM is offloading dynamic PHP execution over the FastCGI Unix domain socket.
