## Key Architecture Takeaways

- **Sublime Text Ingress**: While Sublime Text is a lightweight native desktop editor, developers can seamlessly edit remote Linux files without heavy virtual network file systems.
- **The `rsub` / `rmate` Paradigm**: Uses reverse SSH port forwarding (`TCP 52698`) to open files directly from remote terminal shells into your local desktop Sublime Text editor.
- **Zero Local Footprint**: Edits stream in real time over the existing SSH connection; no duplicate local workspaces or out-of-sync directory caches are created.
- **Robust FUSE Alternative**: For exploring entire directory trees, SSHFS with `reconnect` and `ServerAliveInterval` options provides native OS filesystem integration.

<Callout type="tip" title="Why Reverse SSH Tunnels Outperform Legacy Drive Mounts">
Legacy drive mounters like ExpanDrive or Win-SSHFS poll directory trees continuously, consuming high CPU and hanging whenever network latency spikes. Reverse tunneling with `rsub` consumes zero idle bandwidth and opens files only when you explicitly invoke them in the terminal.
</Callout>

## Method 1: Reverse SSH Tunneling with rsub (Recommended)

`rsub` (an implementation of TextMate's `rmate` protocol for Sublime Text) allows you to run a single command in your remote SSH session to open any file directly inside your local desktop Sublime editor.

<Steps>

### Install the rsub Package in Sublime Text

1. In Sublime Text, press `Ctrl+Shift+P` (or `Cmd+Shift+P` on macOS) to open the Command Palette.
2. Select **Package Control: Install Package**.
3. Type **rsub** and press Enter to install the listener package.
4. The rsub background listener will automatically bind to `localhost:52698` on your desktop.

### Configure Your SSH Client for Reverse Port Forwarding

To route remote server requests back to your local Sublime listener, configure reverse port forwarding (`-R 52698:localhost:52698`) in your SSH manifest:

<CodeTabs tabs={[
  {
    filename: "~/.ssh/config",
    language: "apacheconf",
    content: `# Remote Server with Sublime Reverse Tunnel
Host remote-vps
    HostName 198.51.100.30
    User sysadmin
    IdentityFile ~/.ssh/id_ed25519
    # Forward remote port 52698 to local desktop port 52698
    RemoteForward 52698 127.0.0.1:52698
    ServerAliveInterval 30
`
  },
  {
    filename: "connect-command.sh",
    language: "bash",
    content: `# Or connect with manual flag from the command line:
ssh -R 52698:localhost:52698 sysadmin@198.51.100.30
`
  }
]} />

### Install the `rmate` Helper Script on the Linux Server

On the remote Linux server, download the standalone POSIX shell script:

```bash
# Download rmate script into system binary PATH
sudo curl -fsSL https://raw.githubusercontent.com/aurora/rmate/master/rmate -o /usr/local/bin/rsub

# Grant executable permissions
sudo chmod +x /usr/local/bin/rsub
```

### Edit Remote Files Directly

Now, while inside your remote SSH terminal session, simply type:

```bash
# Opens remote Nginx configuration in your local desktop Sublime Text
rsub /etc/nginx/sites-available/default
```

When you press `Ctrl+S` (or `Cmd+S`) in Sublime Text, the modifications are instantly encrypted and saved directly to the remote Linux filesystem.

</Steps>

## Method 2: High-Performance SSHFS FUSE Mount

If your project requires viewing the entire project tree and performing global text searches across hundreds of files in Sublime Text, mount the remote filesystem using modern SSHFS:

<CodeTabs tabs={[
  {
    filename: "mount-sshfs-linux.sh",
    language: "bash",
    content: `# Create local mountpoint
mkdir -p ~/remote-projects/app-server

# Mount with hardened keep-alives and cache tuning
sshfs -o reconnect,ServerAliveInterval=15,ServerAliveCountMax=3,idmap=user,Ciphers=chacha20-poly1305@openssh.com sysadmin@198.51.100.30:/var/www/html ~/remote-projects/app-server

# Launch Sublime Text on the mounted workspace
subl ~/remote-projects/app-server
`
  },
  {
    filename: "unmount-clean.sh",
    language: "bash",
    content: `# Safely unmount when development session concludes
fusermount -u ~/remote-projects/app-server
`
  }
]} />
