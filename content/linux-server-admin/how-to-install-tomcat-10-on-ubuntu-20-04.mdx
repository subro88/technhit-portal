## Key Architecture Takeaways

- **Jakarta EE 10 Namespace Shift**: Tomcat 10 marks the monumental migration from `javax.servlet` to `jakarta.servlet` (Servlet 6.0 / JSP 3.1). Legacy Java servlets must be refactored or converted using the Apache Tomcat Migration Tool.
- **Enterprise JVM Runtime**: Tomcat 10.1 runs optimally on **OpenJDK 21 LTS** or **OpenJDK 17 LTS**. Configure `-XX:+UseG1GC` and `-XX:MaxGCPauseMillis=200` to prevent destructive stop-the-world GC pauses under concurrent web traffic.
- **Strict Process Sandboxing**: The Tomcat daemon must run under a dedicated unprivileged system account (`tomcat`) with `/usr/sbin/nologin` shell. Hardened systemd configurations enforce `ProtectSystem=strict` and isolate temporary directories with `PrivateTmp=yes`.
- **Edge Reverse Proxying**: In production, never expose Tomcat port 8080 directly to WAN. Bind Tomcat to loopback (`127.0.0.1:8080`) behind an Nginx reverse proxy terminating TLS 1.3, forwarding real client headers via `RemoteIpValve`.

## 1. Architectural Overview: The Jakarta EE 10 Servlet Container

Apache Tomcat 10 is an open-source implementation of the **Jakarta Servlet**, **Jakarta Server Pages (JSP)**, and **Jakarta WebSocket** technologies. Unlike lightweight Python or Node runtimes, Tomcat operates a layered container architecture designed for concurrent multi-threaded execution within the Java Virtual Machine.

<ArchitectureDiagram type="tomcat-servlet" />

### Container Subsystem Hierarchy

1. **Coyote NIO Connector**: The protocol handler listening on port 8080. It uses non-blocking Java I/O (`NioEndpoint`) to multiplex thousands of concurrent client keep-alive TCP connections across a fixed worker thread pool (`maxThreads="200"`).
2. **Catalina Engine**: The top-level servlet container responsible for evaluating incoming HTTP requests, executing pipeline valves, and delegating execution to the appropriate Virtual Host (`<Host name="localhost">`).
3. **Context / Webapps**: Represents individual web applications (`.war` archives or unpacked directories under `/opt/tomcat/webapps/`). Each Context possesses an isolated class loader hierarchy, preventing dependency collisions across applications.
4. **Valves Pipeline**: Interceptors placed within Catalina to handle cross-cutting concerns: `AccessLogValve` for structured request logging, and `RemoteIpValve` for extracting real client IPs from upstream reverse proxies.

### Enforcing Strict POSIX File Permissions

A critical security flaw in naive tutorials is running `chmod -R 777` or giving ownership of the entire directory tree to the `tomcat` user. If the `tomcat` user owns the binaries (`bin/`) and configuration (`conf/`), a compromised servlet can rewrite its own startup scripts or tamper with `server.xml`.

<CodeTabs tabs={[
  {
    name: "Hardened Permissions Script",
    language: "bash",
    content: `# 1. Assign base directory ownership to tomcat user and group
sudo chown -R tomcat:tomcat /opt/tomcat

# 2. Make startup scripts executable by the tomcat user
sudo chmod -R u+x /opt/tomcat/bin

# 3. Restrict conf/ to root:tomcat with 0750 permissions
# Only root and members of the tomcat group can access configuration files
sudo chown -R root:tomcat /opt/tomcat/conf
sudo chmod 0750 /opt/tomcat/conf

# 4. Strictly lock down password files to 0640
sudo chmod 0640 /opt/tomcat/conf/tomcat-users.xml
sudo chmod 0640 /opt/tomcat/conf/server.xml`
  }
]} />

## 4. Step 3: Configuring Administrative RBAC (`tomcat-users.xml`)

Access to the Tomcat Web Application Manager (`/manager/html`) and Virtual Host Manager (`/host-manager/html`) is governed by XML-based Role-Based Access Control (RBAC).

Edit `/opt/tomcat/conf/tomcat-users.xml`:

```xml
<tomcat-users xmlns="http://tomcat.apache.org/xml"
              xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
              xsi:schemaLocation="http://tomcat.apache.org/xml tomcat-users.xsd"
              version="1.0">

  <!-- Define administrative roles -->
  <role rolename="manager-gui"/>
  <role rolename="manager-script"/>
  <role rolename="admin-gui"/>

  <!-- Restricted operator account (Replace 'ChangeMe_StrictPass_2026!' with a strong credential) -->
  <user username="sysadmin" 
        password="ChangeMe_StrictPass_2026!" 
        roles="manager-gui,admin-gui,manager-script"/>
</tomcat-users>
```

<Callout type="warning" title="Manager Console Remote Address Restriction">
By default, Tomcat restricts access to `/manager` and `/host-manager` strictly to localhost (`127.0.0.1` / `::1`) via a `RemoteAddrValve` inside `/opt/tomcat/webapps/manager/META-INF/context.xml`. Never comment out this valve to allow `0.0.0.0/0`! Doing so exposes your admin console to automated credential stuffing attacks across the internet. Instead, manage Tomcat via an SSH tunnel or behind an authenticated reverse proxy.
</Callout>

## 5. Step 4: Enterprise Systemd Unit with JVM Memory & G1GC Calibration

Create a production-grade systemd service file at `/etc/systemd/system/tomcat.service`.

[Service]
Type=forking

User=tomcat
Group=tomcat

# Environment variables
Environment="JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64"
Environment="JAVA_OPTS=-Djava.awt.headless=true -Djava.security.egd=file:/dev/./urandom"
Environment="CATALINA_HOME=/opt/tomcat"
Environment="CATALINA_BASE=/opt/tomcat"
Environment="CATALINA_PID=/opt/tomcat/temp/tomcat.pid"

# Production JVM Heap & G1GC Memory Calibration:
# -Xms: Initial heap size (set equal to -Xmx to avoid runtime heap allocation overhead)
# -Xmx: Maximum heap size (allocate 50-70% of available server RAM)
# -XX:+UseG1GC: Low-latency regional Garbage-First collector
# -XX:MaxGCPauseMillis=200: Soft ceiling for GC collection pauses
Environment="CATALINA_OPTS=-Xms2048M -Xmx2048M -server -XX:+UseG1GC -XX:MaxGCPauseMillis=200 -XX:+ParallelRefProcEnabled -XX:+AlwaysPreTouch"

ExecStart=/opt/tomcat/bin/startup.sh
ExecStop=/opt/tomcat/bin/shutdown.sh

PrivateTmp=yes

[Install]
WantedBy=multi-user.target`
  }
]} />

### Reload Systemd and Enable Service

```bash
# Reload systemd manager configuration
sudo systemctl daemon-reload

# Enable service to start on system boot
sudo systemctl enable tomcat

# Start the Tomcat daemon
sudo systemctl start tomcat

# Verify active status
sudo systemctl status tomcat --no-pager
```

## 6. Step 5: Production Nginx Edge Reverse Proxy & RemoteIpValve

To deliver high performance and industry standard security, place Tomcat behind **Nginx** acting as a TLS 1.3 termination proxy.

### A. Enable `RemoteIpValve` in Tomcat (`conf/server.xml`)

Edit `/opt/tomcat/conf/server.xml` and locate the `<Host name="localhost">` block. Insert the `RemoteIpValve` to ensure Tomcat logs the real client IP and acknowledges HTTPS requests:

```xml
<Host name="localhost"  appBase="webapps" unpackWARs="true" autoDeploy="true">

  <!-- Ingest X-Forwarded-For & X-Forwarded-Proto from Nginx -->
  <Valve className="org.apache.catalina.valves.RemoteIpValve"
         internalProxies="127\.0\.0\.1|::1"
         remoteIpHeader="x-forwarded-for"
         protocolHeader="x-forwarded-proto" />

  <!-- Existing AccessLogValve follows... -->
</Host>
```

### B. Configure Nginx VirtualHost (`/etc/nginx/sites-available/tomcat.conf`)

<CodeTabs tabs={[
  {
    name: "Nginx Reverse Proxy Config",
    language: "nginx",
    content: `server {
    listen 80;
    listen [::]:80;
    server_name java.nhit.in;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name java.nhit.in;

    ssl_certificate /etc/letsencrypt/live/java.nhit.in/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/java.nhit.in/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    access_log /var/log/nginx/tomcat_access.log;
    error_log /var/log/nginx/tomcat_error.log;

    # Pass traffic to local Tomcat Coyote NIO connector
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket support
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # Buffer & Timeout calibrations
        proxy_connect_timeout 60s;
        proxy_read_timeout 120s;
        proxy_buffer_size 16k;
        proxy_buffers 4 64k;
    }
}`
  }
]} />
