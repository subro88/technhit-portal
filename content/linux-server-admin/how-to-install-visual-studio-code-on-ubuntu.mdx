## Key Architecture Takeaways

- **Modern GPG Keyring Security**: Deprecated `apt-key add` has been replaced by isolated, de-armored GPG keys stored in `/etc/apt/keyrings/packages.microsoft.gpg`.
- **Packaging Paradigm Trade-Offs**: Native DEB packages provide zero-overhead filesystem and hardware acceleration access, whereas Canonical Snap packages offer automated sandboxed confinement.
- **Headless Terminal Integration**: VS Code includes the native `code` CLI, enabling immediate workspace launching, diffing (`code --diff file1 file2`), and headless server tunneling.
- **Enterprise Upgrade Pipeline**: Configuring the signed Microsoft repository guarantees seamless unattended security updates via `apt update && apt upgrade`.

<Callout type="tip" title="Modern Keyring Standard in Ubuntu 24.04">
Ubuntu 22.04 and 24.04 LTS deprecated `apt-key`. Adding third-party repository keys directly to `/etc/apt/trusted.gpg` is insecure because it grants the repository signing authority over every package on your system. Always isolate repository signing keys using the `signed-by` attribute.
</Callout>

## Deployment Methods: Native APT vs. Confined Snap

When deploying VS Code on developer workstations, engineering teams choose between two primary packaging strategies:

| Vector | Official Microsoft APT (`.deb`) | Canonical Snap (`--classic`) |
| :--- | :--- | :--- |
| **Filesystem Access** | Full native POSIX permissions | Classic confinement (unconfined host access) |
| **Update Mechanism** | Managed via standard `apt upgrade` | Automatic background updates via `snapd` |
| **Startup Overhead** | Zero overhead; native shared libraries | Slightly slower cold start due to squashfs mount |
| **Architecture** | amd64, arm64, armhf | amd64, arm64, armhf |
| **Best Used For** | Bare-metal workstations, embedded compilers | Desktops seeking automatic maintenance |

## Installing via Official Microsoft APT Repository

<Steps>

### Install Core Cryptographic Dependencies

Ensure system utilities for fetching remote keys and managing transport HTTPS are installed:

```bash
# Update package lists and install curl & gpg
sudo apt update
sudo apt install -y curl gpg apt-transport-https
```

### Import and De-Armor the Microsoft GPG Signing Key

Download Microsoft's ASCII-armored public key, de-armor it into binary format, and place it in the secure `/etc/apt/keyrings/` system directory:

```bash
# Create dedicated keyrings directory with hardened permissions
sudo install -m 0755 -d /etc/apt/keyrings

# Fetch and de-armor Microsoft repository key
curl -fsSL https://packages.microsoft.com/keys/microsoft.asc | gpg --dearmor | sudo tee /etc/apt/keyrings/packages.microsoft.gpg > /dev/null

# Set proper read permissions
sudo chmod 0644 /etc/apt/keyrings/packages.microsoft.gpg
```

### Provision the Signed Repository Source List

Inject the repository definition into `/etc/apt/sources.list.d/vscode.list`, referencing the isolated keyring:

```bash
# Append repository configuration with explicit signed-by directive
echo "deb [arch=amd64,arm64,armhf signed-by=/etc/apt/keyrings/packages.microsoft.gpg] https://packages.microsoft.com/repos/code stable main" | sudo tee /etc/apt/sources.list.d/vscode.list > /dev/null
```

### Install Visual Studio Code

Synchronize package indexes and execute the package installation:

```bash
# Refresh index including Microsoft mirror
sudo apt update

# Install Visual Studio Code
sudo apt install -y code
```

</Steps>

## Alternative: Installing via Snapcraft

For automated continuous updates without manual repository maintenance:

```bash
# Install Visual Studio Code with classic system confinement
sudo snap install --classic code
```

Verification of the installed snap version:
```bash
snap list code
```
