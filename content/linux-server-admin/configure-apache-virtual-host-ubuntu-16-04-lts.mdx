## Key Architecture Takeaways

- **Name-Based Virtual Hosting**: Apache 2.4 multiplexes hundreds of unique domain names across a single public IP address using the HTTP `Host` header and TLS **Server Name Indication (SNI)**.
- **Tenant Sandboxing**: Each VirtualHost must point to a dedicated `DocumentRoot` (e.g., `/var/www/site1/public`) owned by an isolated tenant user with `0750` permissions to prevent cross-account directory traversal.
- **Directory Index Defense**: Always enforce `Options -Indexes` within `<Directory>` blocks. Leaving `Options Indexes` enabled exposes file trees, database dumps, and configuration secrets whenever an `index.html` or `index.php` is missing.
- **Segregated Access & Error Streams**: Direct each VirtualHost to dedicated log files (`${APACHE_LOG_DIR}/site1_error.log`), isolating diagnostic audit trails and preventing noisy-neighbor log corruption.

## 1. Architectural Overview: How Apache Resolves VirtualHosts

When an HTTP/1.1 or HTTP/2 client initiates a TCP socket connection to port 80 or 443, it transmits an SNI handshake (under TLS) and an HTTP `Host:` request header containing the target Fully Qualified Domain Name (FQDN).

<ArchitectureDiagram type="apache-vhost" />

### The Resolution Pipeline

1. **IP & Port Match**: Apache filters active `<VirtualHost>` containers matching the ingress socket (e.g. `*:80` or `*:443`).
2. **ServerName & ServerAlias Evaluation**: The core dispatcher compares the client's `Host:` header against `ServerName` and `ServerAlias` directives across all enabled configuration files in `/etc/apache2/sites-enabled/`.
3. **Fallback to Default**: If no `ServerName` matches, Apache routes the request to the first alphabetically loaded VirtualHost (conventionally `000-default.conf`).
4. **Execution Sandbox**: Apache applies the corresponding `<Directory>` stanza, enforcing `Options`, `AllowOverride`, and handler mappings before serving static assets or executing dynamic FastCGI backends.

## 3. Creating Hardened VirtualHost Configurations

Avoid putting all virtual hosts in a single configuration file. Store each domain configuration separately in `/etc/apache2/sites-available/`.

### Configuration A: `alpha.nhit.in.conf`

```apache
<VirtualHost *:80>
    ServerName alpha.nhit.in
    ServerAlias www.alpha.nhit.in
    ServerAdmin webmaster@alpha.nhit.in
    DocumentRoot /var/www/alpha.nhit.in/public

    <Directory /var/www/alpha.nhit.in/public>
        # SECURITY: Explicitly disable directory listing (-Indexes)
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>

    # Dedicated log streams
    LogLevel warn
    ErrorLog ${APACHE_LOG_DIR}/alpha_error.log
    CustomLog ${APACHE_LOG_DIR}/alpha_access.log combined
</VirtualHost>
```

### Configuration B: `beta.nhit.in.conf`

```apache
<VirtualHost *:80>
    ServerName beta.nhit.in
    ServerAlias www.beta.nhit.in
    ServerAdmin webmaster@beta.nhit.in
    DocumentRoot /var/www/beta.nhit.in/public

    <Directory /var/www/beta.nhit.in/public>
        # SECURITY: Explicitly disable directory listing (-Indexes)
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>

    # Dedicated log streams
    LogLevel warn
    ErrorLog ${APACHE_LOG_DIR}/beta_error.log
    CustomLog ${APACHE_LOG_DIR}/beta_access.log combined
</VirtualHost>
```

## 4. Activating VirtualHosts & Syntax Verification

Never reload the Apache service without first executing an automated syntax check (`apache2ctl configtest`). Applying an edit with a missing tag or typo crashes the production web server immediately.
