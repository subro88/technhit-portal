## Key Architecture Takeaways

- **Memory Hierarchy Latency Gap**: Registers (1 cycle, ~0.5ns) and L1/L2 caches are orders of magnitude faster than DRAM (~100ns) and NVMe/SSD storage (~10-100µs), necessitating multi-tiered caching strategies.
- **Kernel vs. User Space Boundary**: Modern operating systems enforce hardware ring-0 kernel protection; unprivileged applications interact with physical devices exclusively through audited POSIX system calls (`syscall`).
- **Virtual Memory & MMU**: The Memory Management Unit translates process-isolated virtual memory addresses to physical RAM frames via multi-level page tables, preventing cross-process memory corruption.
- **Protocol Encapsulation**: Network data units transform systematically down the stack: Application Data -> TCP Segments (Port addressing) -> IP Packets (Routing) -> Ethernet Frames (MAC addressing) -> Physical Bits.

## 1. Processor Microarchitecture & Memory Hierarchy

The modern Central Processing Unit (CPU) implements the classic von Neumann instruction cycle: **Fetch, Decode, Execute, and Writeback**.

```text
+-------------------------------------------------------------------------+
|                              CPU DIE                                    |
|  +--------------------+  +--------------------+  +-------------------+  |
|  |  Registers (64-bit)|  | ALU (Math / Logic) |  | Control Unit (CU) |  |
|  +--------------------+  +--------------------+  +-------------------+  |
|            |                        |                       |           |
|            v                        v                       v           |
|  +-------------------------------------------------------------------+  |
|  |             L1 Cache (32KB Data + 32KB Instruction, ~1ns)         |  |
|  +-------------------------------------------------------------------+  |
|                                    |                                    |
|  +-------------------------------------------------------------------+  |
|  |                   L2 Cache (512KB - 1MB, ~4ns)                    |  |
|  +-------------------------------------------------------------------+  |
|                                    |                                    |
|  +-------------------------------------------------------------------+  |
|  |                   L3 Shared Cache (16MB - 96MB, ~15ns)            |  |
|  +-------------------------------------------------------------------+  |
+-------------------------------------------------------------------------+
                                    |
                             DDR5 RAM (~60ns)
                                    |
                            NVMe Storage (~20µs)
```

### Key Hardware Components

- **Arithmetic Logic Unit (ALU)**: Executes fundamental binary operations including addition, bitwise AND/OR/XOR, and two's complement subtraction.
- **Control Unit (CU)**: Decodes instruction opcodes from memory and generates synchronization signals across the address and data buses.
- **Registers**: Ultra-high-speed static storage cells inside the processor core:
  - `RIP` (Instruction Pointer / Program Counter): Points to the memory address of the next machine instruction.
  - `RSP` (Stack Pointer): Tracks the top of the current execution call stack in memory.
  - `RAX / RBX / RCX / RDX`: General-purpose registers for arithmetic and syscall arguments.

## 2. Operating System Kernel & Process Lifecycle

The Linux operating system separates execution privileges using hardware CPU protection rings: **Ring 0 (Kernel Space)** has unrestricted access to bare-metal hardware and RAM, while **Ring 3 (User Space)** runs sandboxed unprivileged applications.

### Process Creation via Fork and Execve

Linux spawns processes using the `fork()` and `execve()` system call pair:

```bash
# 1. fork(): Duplicates the calling process with Copy-on-Write (CoW) page tables
# 2. execve(): Replaces the memory space with a new compiled ELF binary
```

### Process State Transitions

At any millisecond, a POSIX thread exists in one of four states:

1. **Running (`R`)**: Actively executing machine instructions on a physical or virtual CPU core.
2. **Interruptible Sleep (`S`)**: Waiting for an event, such as network socket data, disk I/O, or a timer tick.
3. **Uninterruptible Sleep (`D`)**: Waiting on direct hardware disk or NFS controller I/O; cannot be terminated by `SIGKILL`.
4. **Zombie (`Z`)**: Terminated process whose return code has not yet been collected by its parent process via `wait4()`.

## 3. Storage Subsystems, Inodes & Virtual Memory

Storage is organized into distinct logical abstractions:

- **Block Devices**: Physical storage devices (`/dev/nvme0n1`, `/dev/sda`) transfer data in fixed-size blocks (typically 4096 bytes / 4KB).
- **Inodes**: Data structures on disk storing file metadata, permissions (`chmod`), ownership (`chown`), timestamps (atime, mtime, ctime), and pointers to data blocks. The filename itself is stored in directory entries (**dentries**), not inside the inode.
- **Virtual Memory Paging**: The Memory Management Unit (MMU) divides virtual memory into 4KB pages. If a program attempts to access an address not currently mapped to physical DRAM, the CPU raises a **Page Fault** exception, triggering the kernel to read the page from disk or swap.

## 4. Computer Networking & Protocol Encapsulation

Modern internet communication operates on the unified TCP/IP four-layer architecture:

| Layer | Protocol Examples | Addressing | Data Unit |
| :--- | :--- | :--- | :--- |
| **Application (Layer 7)** | HTTP/2, SSH, DNS, TLS | URI / Hostname / Domain | Message / Stream |
| **Transport (Layer 4)** | TCP, UDP, QUIC | Port (e.g. 80, 443, 22) | Segment / Datagram |
| **Network (Layer 3)** | IPv4, IPv6, ICMP, BGP | IP Address (`198.51.100.1`) | Packet |
| **Data Link (Layer 2)** | Ethernet (802.3), Wi-Fi (802.11) | MAC Address (`00:1A:2B:3C:4D:5E`) | Frame |

### The TCP Three-Way Handshake

Reliable TCP connections establish connection state through a deterministic three-step exchange:

```text
Client                                  Server
  |                                       |
  | -------- SYN (Seq=X) ---------------> |  1. Client initiates connection
  |                                       |
  | <------- SYN-ACK (Seq=Y, Ack=X+1) --- |  2. Server acknowledges and responds
  |                                       |
  | -------- ACK (Ack=Y+1) -------------> |  3. Client confirms; Connection ESTABLISHED
  |                                       |
```

## 5. Digital Logic & Data Representation

At the physical silicon layer, computers operate on binary voltage states:

- **Bit**: A single binary digit (`0` or `1`), representing the conductive state of a CMOS field-effect transistor (MOSFET).
- **Byte**: Exactly 8 bits, capable of representing $2^8 = 256$ distinct values (`0x00` through `0xFF`).
- **Two's Complement**: The standard mathematical representation for signed integers in computing. To invert a number, flip all bits and add 1 ($A_{\text{negative}} = \sim A + 1$).
- **Character Encoding**:
  - **ASCII**: 7-bit encoding representing 128 standard English characters and control codes.
  - **UTF-8**: Variable-length encoding (1 to 4 bytes per character) that is 100% backwards-compatible with ASCII while supporting every international language, mathematical symbol, and emoji.
