## Key Architecture Takeaways

- **Name-Based VirtualHost Routing**: Apache's HTTP engine inspects the incoming `Host:` request header and TLS SNI extension to dispatch traffic to isolated `<VirtualHost>` blocks on a single public IP address.
- **Strict POSIX Directory Sandboxing**: DocumentRoots under `/var/www/<domain>/public` are configured with `0750` permissions and `www-data` group ownership, preventing cross-tenant file traversal.
- **Information Disclosure Mitigation**: Setting `Options -Indexes` stops directory browsing if `index.html` is missing, preventing automated reconnaissance of sensitive server files.
- **Pre-Flight Configuration Testing**: Running `sudo apache2ctl configtest` catches syntax mistakes before reloading the daemon, preventing accidental cluster outages.

## Name-Based Multi-Tenancy & POSIX Isolation Topology

In shared and multi-tenant hosting environments, running multiple independent web applications on one server requires clear separation between network dispatch, filesystem permissions, and diagnostic logging.

<ArchitectureDiagram type="apache-vhost" title="Apache 2.4 Name-Based VirtualHost Multi-Tenancy Mesh" />

<Callout type="benchmark" title="The Multi-Tenancy Dilemma: Name-Based vs IP-Based VHosts">
IP-based VirtualHosting requires reserving a dedicated, routable public IPv4 address for every website, which is financially prohibitive under modern IPv4 exhaustion. 

**Name-based VirtualHosting** allows thousands of domains to share a single public IPv4 and IPv6 address. When a client initiates an HTTP/1.1 or HTTP/2 connection, the browser transmits the target domain name in the `Host:` header (and in the TLS ClientHello Server Name Indication / SNI extension), allowing Apache to immediately route the request to the correct `<VirtualHost>` definition in `< 0.1ms`.
</Callout>

## Directory Hierarchy & File Organization

Before creating configuration files, review the standard Debian/Ubuntu Apache layout:

<FileTree>
- /etc/apache2/
  - apache2.conf // Global master server configuration
  - ports.conf // Listen 80 and Listen 443 bindings
  - sites-available/
    - alpha.nhit.in.conf (highlight) // Tenant A VirtualHost configuration
    - beta.nhit.in.conf (highlight) // Tenant B VirtualHost configuration
  - sites-enabled/
    - alpha.nhit.in.conf (highlight) // Symlink created via a2ensite
    - beta.nhit.in.conf (highlight) // Symlink created via a2ensite
- /var/www/
  - alpha.nhit.in/
    - public/ (highlight) // Tenant A DocumentRoot (chmod 0750)
  - beta.nhit.in/
    - public/ (highlight) // Tenant B DocumentRoot (chmod 0750)
- /var/log/apache2/
  - alpha_error.log (highlight) // Dedicated error telemetry for Tenant A
  - beta_error.log (highlight) // Dedicated error telemetry for Tenant B
</FileTree>

## Step-by-Step Implementation Guide

<Steps>
  <Step title="Update Repositories and Install Apache 2.4">
    Ensure your server package manager is updated and install the latest stable Apache HTTP server release:

    <TerminalBlock
      command="sudo apt update && sudo apt install -y apache2"
      title="Install Apache HTTP Server"
      os="Ubuntu 20.04 / 22.04 / 24.04 LTS"
    />

    Enable and start the `apache2` service via systemd:

    <TerminalBlock
      command="sudo systemctl enable --now apache2 && sudo systemctl status apache2 --no-pager"
      title="Verify Daemon Status"
      os="Systemd"
    />
  </Step>

  <Step title="Create Isolated DocumentRoots for Multiple Domains">
    In enterprise systems, avoid hosting files in `/home/user/public_html` due to permission conflicts and SELinux/AppArmor denials. Use the standard `/var/www/<domain>/public` hierarchy:

    <TerminalBlock
      command="sudo mkdir -p /var/www/alpha.nhit.in/public /var/www/beta.nhit.in/public"
      title="Create Isolated Web DocumentRoots"
      os="Linux"
    />

    Create testing `index.html` landing pages for each domain:

    <CodeTabs>
      <div label="/var/www/alpha.nhit.in/public/index.html" filename="/var/www/alpha.nhit.in/public/index.html">
```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Alpha Tenant | TechNHIT</title>
</head>
<body style="font-family: sans-serif; background: #07090e; color: #00f5d4; padding: 2rem;">
  <h1>VirtualHost alpha.nhit.in Online</h1>
  <p>Production document root: /var/www/alpha.nhit.in/public</p>
</body>
</html>
```
      </div>

      <div label="/var/www/beta.nhit.in/public/index.html" filename="/var/www/beta.nhit.in/public/index.html">
```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Beta Tenant | TechNHIT</title>
</head>
<body style="font-family: sans-serif; background: #07090e; color: #bd00ff; padding: 2rem;">
  <h1>VirtualHost beta.nhit.in Online</h1>
  <p>Production document root: /var/www/beta.nhit.in/public</p>
</body>
</html>
```
      </div>
    </CodeTabs>
  </Step>

  <Step title="Enforce Strict POSIX Ownership & 0750 Permissions">
    Never use `chmod 777`! Grant the web server read and execute access while keeping tenant files isolated:

    <TerminalBlock
      command="sudo chown -R www-data:www-data /var/www && sudo chmod -R 750 /var/www"
      title="Enforce Principle of Least Privilege"
      os="Linux"
    />
  </Step>

  <Step title="Author Name-Based VirtualHost Configurations">
    Create `/etc/apache2/sites-available/alpha.nhit.in.conf` with disabled directory indexes, `.htaccess` overrides enabled, and dedicated logging:

    <CodeTabs>
      <div label="/etc/apache2/sites-available/alpha.nhit.in.conf" filename="/etc/apache2/sites-available/alpha.nhit.in.conf">
```apache
# ==============================================================================
# TechNHIT VirtualHost Configuration: alpha.nhit.in
# ==============================================================================

<VirtualHost *:80>
    ServerAdmin sysadmin@nhit.in
    ServerName alpha.nhit.in
    ServerAlias www.alpha.nhit.in

    DocumentRoot /var/www/alpha.nhit.in/public

    <Directory /var/www/alpha.nhit.in/public>
        # Disable directory browsing (-Indexes) and follow symlinks
        Options -Indexes +FollowSymLinks
        # Allow .htaccess files to override routing rules
        AllowOverride All
        # Grant public web access
        Require all granted
    </Directory>

    # Dedicated log streams for isolated auditing
    LogLevel warn
    ErrorLog ${APACHE_LOG_DIR}/alpha_error.log
    CustomLog ${APACHE_LOG_DIR}/alpha_access.log combined
</VirtualHost>
```
      </div>

      <div label="/etc/apache2/sites-available/beta.nhit.in.conf" filename="/etc/apache2/sites-available/beta.nhit.in.conf">
```apache
# ==============================================================================
# TechNHIT VirtualHost Configuration: beta.nhit.in
# ==============================================================================

<VirtualHost *:80>
    ServerAdmin sysadmin@nhit.in
    ServerName beta.nhit.in
    ServerAlias www.beta.nhit.in

    DocumentRoot /var/www/beta.nhit.in/public

    <Directory /var/www/beta.nhit.in/public>
        Options -Indexes +FollowSymLinks
        AllowOverride All
        Require all granted
    </Directory>

    LogLevel warn
    ErrorLog ${APACHE_LOG_DIR}/beta_error.log
    CustomLog ${APACHE_LOG_DIR}/beta_access.log combined
</VirtualHost>
```
      </div>
    </CodeTabs>
  </Step>

  <Step title="Enable Sites and Perform Pre-Flight Configtest">
    Use the native `a2ensite` command to create atomic symlinks into `sites-enabled/`:

    <TerminalBlock
      command="sudo a2ensite alpha.nhit.in.conf beta.nhit.in.conf"
      title="Enable VirtualHost Configurations"
      os="Apache 2.4"
    />

    **CRITICAL**: Execute a syntax check before touching the running daemon:

    <TerminalBlock
      command="sudo apache2ctl configtest"
      title="Execute Pre-Flight Syntax Validation"
      os="Apache 2.4"
    />

    Expected output:
    ```bash
    Syntax OK
    ```
    If any errors appear, correct the specified line before proceeding.
  </Step>

  <Step title="Reload Apache Service with Zero Downtime">
    Apply the new configuration gracefully using `reload` instead of `restart`, preserving active HTTP connections:

    <TerminalBlock
      command="sudo systemctl reload apache2"
      title="Zero-Downtime Service Reload"
      os="Systemd"
    />
  </Step>

  <Step title="Test Name-Based VirtualHost Dispatch">
    Verify that each domain is routed accurately by sending HTTP requests with explicit `Host:` headers:

    <TerminalBlock
      command="curl -s -H 'Host: alpha.nhit.in' http://127.0.0.1/ | grep -i 'alpha'"
      title="Verify Alpha Tenant Routing"
      os="Linux"
    />

    <TerminalBlock
      command="curl -s -H 'Host: beta.nhit.in' http://127.0.0.1/ | grep -i 'beta'"
      title="Verify Beta Tenant Routing"
      os="Linux"
    />
  </Step>
</Steps>
