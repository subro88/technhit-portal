## Why Multi-PHP Isolation is Vital

When managing production servers for hosting multiple web applications, legacy monoliths often require older runtimes (e.g., PHP 5.6 or 7.4) while newer microservices demand modern versions (PHP 8.2 / 8.3). Managing these conflicting runtimes on a single server without virtualization overhead requires dedicated PHP-FPM UNIX sockets mapped per VirtualHost.

## Prerequisites & Baseline Setup

- One Linux server running Ubuntu 20.04 / 22.04 / 24.04 LTS or Debian 12.
- A user account with `sudo` administrative privileges.
- Network connectivity with ports 80 (HTTP) and 443 (HTTPS) open.

<Callout type="info" title="Zero Overhead Architecture">
UNIX domain sockets bypass TCP network stack processing entirely, providing up to 25% lower request latency compared to loopback TCP sockets (`127.0.0.1:9000`).
</Callout>

## Step 1: Install Apache and mod_fcgid

Update your apt package cache and install Apache along with the FastCGI daemon module:

```bash
sudo apt update
sudo apt install -y apache2 libapache2-mod-fcgid
```

## Step 2: Install Multiple PHP-FPM Pools

Add the Ondřej Surý PHP repository to access all historical and modern PHP versions:

```bash
sudo apt install -y software-properties-common
sudo add-apt-repository -y ppa:ondrej/php
sudo apt update 
sudo apt install -y php5.6 php5.6-fpm php7.4 php7.4-fpm
```

<Callout type="warning" title="PHP-FPM Socket Permissions">
Verify that each PHP pool configuration in `/etc/php/<version>/fpm/pool.d/www.conf` sets `listen.owner = www-data` and `listen.group = www-data`. If permissions mismatch, Apache will fail with `503 Service Unavailable`.
</Callout>

Verify that both PHP-FPM daemons are actively running:

```bash
sudo systemctl status php5.6-fpm
sudo systemctl status php7.4-fpm
```

## Step 3: Configure FastCGI and Proxy Modules

Enable the required proxy modules in Apache to communicate with UNIX sockets:

```bash
sudo a2enmod actions fcgid alias proxy_fcgi
```

Create isolated application document roots for testing both runtimes:

```bash
sudo mkdir -p /var/www/php56-app /var/www/php74-app
echo "<?php phpinfo(); ?>" | sudo tee /var/www/php56-app/index.php
echo "<?php phpinfo(); ?>" | sudo tee /var/www/php74-app/index.php
```

## Step 4: Configure VirtualHosts with UNIX Sockets

Switch between the two site configurations below to inspect how each VirtualHost binds to its respective PHP socket:

<CodeTabs defaultTab={0}>
  <Tab label="PHP 5.6 VirtualHost" lang="apache" filename="/etc/apache2/sites-available/php56.example.com.conf">
<VirtualHost *:80>
    ServerName php56.example.com
    DocumentRoot /var/www/php56-app
    <Directory /var/www/php56-app>
        Options -Indexes +FollowSymLinks +MultiViews
        AllowOverride All
        Require all granted
    </Directory>
    <FilesMatch \.php$>
        SetHandler "proxy:unix:/var/run/php/php5.6-fpm.sock|fcgi://localhost"
    </FilesMatch>
</VirtualHost>
  </Tab>
  <Tab label="PHP 7.4 VirtualHost" lang="apache" filename="/etc/apache2/sites-available/php74.example.com.conf">
<VirtualHost *:80>
    ServerName php74.example.com
    DocumentRoot /var/www/php74-app
    <Directory /var/www/php74-app>
        Options -Indexes +FollowSymLinks +MultiViews
        AllowOverride All
        Require all granted
    </Directory>
    <FilesMatch \.php$>
        SetHandler "proxy:unix:/var/run/php/php7.4-fpm.sock|fcgi://localhost"
    </FilesMatch>
</VirtualHost>
  </Tab>
</CodeTabs>

Activate both sites and restart Apache:

```bash
sudo a2ensite php56.example.com
sudo a2ensite php74.example.com
sudo apache2ctl configtest
sudo systemctl restart apache2
```

## Step 5: Verify Multi-PHP Routing

Test both endpoints locally or by adding DNS host mappings to `/etc/hosts`:

```bash
curl -H "Host: php56.example.com" http://127.0.0.1/ | grep "PHP Version"
curl -H "Host: php74.example.com" http://127.0.0.1/ | grep "PHP Version"
```

Each VirtualHost will independently execute through its designated PHP-FPM socket pool without runtime collision.
